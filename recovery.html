Maintainer password reset

Create a replacement password file.

Choose a new instructor password here. This tool creates an editor-access.js file without asking for the old password.

Creating the file does not reset the live website.
Applying it requires a GitHub account with permission to edit the project repository. The website keeps its current password until the replacement file is published.

1. Choose your new password

Use 12–128 characters and keep a private record. The file contains a password verifier, never the password itself. Nothing is sent to a server.

2. Publish the replacement file

  1. Keep the downloaded file named editor-access.js. Do not upload the password itself.
  2. Sign in to GitHub with an account that can maintain the project. Open the project repository and its main branch.
  3. At the repository root—the same folder as index.html—choose Add file → Upload files. Upload the new editor-access.js, replacing the existing file. Choose Commit changes and confirm.
  4. Wait for the connected Render deployment to show Live. If automatic deployment is off, deploy the latest commit in Render. GitHub Pages also rebuilds from its configured branch.
  5. Open the website and hard refresh: Ctrl + Shift + R on Windows, or ⌘ + Shift + R on Mac. Test the new password in Edit Content and Downloads.

This replaces password settings only. Games, questions, credits, and player data are not part of this file. An older downloaded offline copy keeps its own password until its settings are updated or a fresh copy is exported.

Keep this helper with the project handover files. It works in a modern browser with secure password tools, including supported offline-file browsers. It does not reveal the old password or grant repository access.
